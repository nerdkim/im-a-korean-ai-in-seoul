# 제약

- hook은 Claude가 한국어를 쓰는 turn에서 `korean-rewrite` skill을 불렀는지는 확인하지만, skill을 부른 뒤 쓴 글이 절차를 모두 따랐는지는 보지 않습니다. 그래서 남은 문제는 검사기가 잡는 오류와 경고로만 드러납니다.
- Claude가 skill을 부르지 않은 채 한국어 답변을 마치면 Stop hook은 그 답변이 화면에 나온 뒤에 skill을 부르고 다시 쓰라고 요청합니다. 그래서 첫 답변과 다시 쓴 답변이 함께 보입니다.
- subagent 프롬프트와 한글이 `writing-skill-min-hangul`개보다 적은 글에는 skill을 요구하지 않습니다. 같은 turn에서 두 번 막았는데도 Claude가 skill을 부르지 않으면 hook은 더 막지 않습니다.
- skill과 hook은 Claude Code에서만 동작합니다. Codex나 Gemini CLI가 쓰는 글에는 커밋 메시지 검사만 적용됩니다.
- 영어식 표현, 쉼표, 길이와 빈도 규칙은 경고로만 보고합니다. 경고가 나온 표현도 문맥에 맞으면 그대로 두어도 됩니다. CLI에 `--strict`를 붙이면 경고도 실패로 처리합니다.
- hook은 Write, Edit, MultiEdit, NotebookEdit 도구로 바꾼 문단에서 `review-rules`에 든 규칙의 경고만 Claude에게 알립니다. 같은 규칙에 걸린 같은 표현이 바뀌기 전 문단에도 있으면 알리지 않으므로, 이미 있던 표현을 그 문단에 한 번 더 써도 알리지 않습니다. NotebookEdit 도구로 셀을 고칠 때는 바뀌기 전 셀과 비교하지 않으므로 원래 있던 경고도 알립니다. 알린 표현을 고칠지는 Claude가 문맥을 보고 정합니다.
- 어투와 표기 규칙 위반을 오류로 분류한 것은 프로젝트 정책입니다. 고유명사에 예외가 필요하면 규칙을 조정합니다.
- Stop hook은 이미 표시된 문장을 되돌리지 못합니다. 최종 답변을 읽고 오류가 있으면 재작성을 한 번만 요청합니다. 재작성한 답변은 다시 검사하지 않으므로 고치지 못한 오류나 재작성 중에 생긴 오류는 그대로 남습니다. 구버전 Claude Code에서는 답변을 직접 받는 대신 transcript를 읽으므로 hook이 실행되는 시점까지 기록된 답변만 검사합니다.
- 다른 어투로 쓴 글을 답변에 옮기면 Stop hook이 재작성을 요청합니다. 같은 줄에서 닫은 큰따옴표나 inline code 안은 어투를 검사하지 않지만 fenced code block 안은 어투와 금지 문자(emoji 제외)를 검사합니다.
- 문서에서 `<!-- korean-style-quote -->` 줄과 `<!-- /korean-style-quote -->` 줄 사이에 넣은 글은 검사하지 않습니다. 이 표시는 다른 사람이나 모델이 쓴 글을 그대로 옮겨 적을 때 씁니다. 답변과 커밋 메시지에서는 이 구간도 검사합니다.
- 검사기는 반말을 잡지 못하고, `돼요`, `봐요`처럼 어간과 합쳐진 해요체 어미도 일부 잡지 못합니다. 이런 어미는 Claude가 작성 지침과 skill을 따라 스스로 피해야 합니다. `셸`, `훅`, `스킬` 같은 음차는 기본 규칙에서 잡지 않습니다. 막으려면 `banned-transliteration`에 음차와 대신 쓸 영어를 넣습니다.
- hook 실행 중에 예외가 발생하면 작업은 계속됩니다. 규칙 파일이 유효한지는 `doctor`와 `gate`에서, hook이 연결되었는지는 `doctor`에서 확인합니다.
- output-style은 프로젝트 설정이 로드되어야 적용됩니다. 다른 스타일을 선택한 세션에는 이 지침이 없고, subagent에는 output-style이 적용되지 않습니다.
- 작성 지침에서 보내기 전에 다시 읽고 고치라고 한 부분은 모델에게 주는 지시입니다. hook은 오류로 분류한 위반을 실제로 막지만 영어식 표현은 막지 않습니다.
- 지원하는 확장자의 소스 파일에서는 주석만 검사합니다. 코드 안의 문자열과 지원하지 않는 확장자의 파일은 검사하지 않고, hook과 전체 검사는 프로젝트 밖 경로를 건너뜁니다.
- 전체 검사는 점(`.`)으로 시작하는 디렉터리와 지정한 제외 경로를 건너뜁니다. 일반 편집기로 파일을 고치면 Claude Code hook이 실행되지 않습니다.
- hook은 shell 명령이 파일에 쓰는 경우 가운데 redirection(`>`, `>>`)과 일부 명령만 감지합니다. 이 검사는 보안 장치가 아니며 프로그램이 내부에서 쓰는 파일까지 추적하지 않습니다.
- 설치 스크립트는 설정 파일 가운데 프로젝트 설정(`.claude/settings.json`)만 바꿉니다. 로컬 설정과 조직 정책, 세션 옵션은 프로젝트 설정보다 우선합니다. 그래서 이 가운데 한 곳에서 다른 output-style을 고르면 이 도구의 output-style이 적용되지 않고, hook을 끄면 이 도구의 hook이 실행되지 않습니다. doctor는 프로젝트 설정 파일과 로컬 설정 파일만 확인합니다. 세션에 실제로 적용된 설정은 `/status`로 확인합니다.
- 직접 수정한 규칙은 재설치해도 바뀌지 않으므로 새로 생긴 `review-rules`도 들어가지 않습니다. 이 경우 doctor가 주의 항목으로 표시합니다. 구버전으로 설치한 규칙의 금지 목록과 경고 정책을 새 기본값으로 바꾸려면 `--force`로 재설치합니다. 이때 설치 스크립트가 기존 규칙을 백업합니다.
- 설치한 프로젝트의 gate는 이 도구 저장소의 테스트를 실행하지 않습니다. 자체 검사와 규칙 문서 검사, 전체 파일 검사만 수행합니다.
- 자체 검사는 도구와 함께 배포한 기본 규칙으로 검사기를 검증하므로 사용자가 규칙 값을 바꿔도 실패하지 않습니다. 실제 답변과 문서는 프로젝트 규칙으로 검사합니다.
- 실제 모델을 호출하는 평가는 고정된 입력으로 진행합니다. 모델, effort, 캐시와 서버 상태에 따라 응답과 실행 시간이 달라집니다. 토큰 수와 실행 시간은 따로 보고합니다.
