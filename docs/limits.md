# 제약

- 번역투, 쉼표, 길이와 빈도 규칙은 경고로 보고하며 문맥에 맞는 표현은 그대로 둡니다. CLI에 `--strict`를 붙이면 경고도 실패로 처리합니다.
- 어투와 표기를 오류로 분류한 것은 프로젝트 정책입니다. 인용과 고유명사에 예외가 필요하면 규칙을 조정합니다.
- Stop hook은 이미 표시된 문장을 회수하지 못합니다. 최종 답변을 읽고 오류가 있으면 재작성을 한 번만 요청합니다. 구버전 Claude Code에서는 transcript를 대신 읽으므로 검사하는 시점에 마지막 답변이 아직 기록되지 않았을 수 있습니다.
- hook 실행 중에 예외가 발생하면 작업은 계속됩니다. 규칙 파일이 유효한지는 `doctor`와 `gate`에서, hook이 연결되었는지는 `doctor`에서 확인합니다.
- output-style은 프로젝트 설정이 로드되어야 적용됩니다. 다른 스타일을 선택한 세션에는 이 지침이 없고, subagent에는 output-style이 적용되지 않습니다.
- 소스 파일은 지원하는 확장자의 파일에서 주석만 검사합니다. 코드 안의 문자열과 지원하지 않는 확장자의 파일은 검사하지 않고, hook과 전체 검사는 프로젝트 밖 경로를 건너뜁니다.
- 전체 검사는 점(`.`)으로 시작하는 디렉터리와 지정한 제외 경로를 건너뜁니다. 일반 편집기로 파일을 고치면 Claude hook이 실행되지 않습니다.
- hook은 shell 명령이 파일에 쓰는 경우 가운데 방향 재지정과 일부 명령만 알아봅니다. 이 검사는 보안 장치가 아니며 프로그램이 내부에서 쓰는 파일까지 추적하지 않습니다.
- 설치는 설정 파일 가운데 프로젝트 설정(`.claude/settings.json`)만 변경합니다. 로컬 설정과 조직 정책, 세션 옵션 때문에 output-style이나 hook이 활성화되지 않을 수 있습니다. doctor는 프로젝트 설정 파일과 로컬 설정 파일만 확인합니다. 세션에 실제로 적용된 설정은 `/status`로 확인합니다.
- 직접 수정한 규칙은 재설치해도 바뀌지 않습니다. 구버전으로 설치한 규칙의 금지 목록과 경고 정책을 새 기본값으로 바꾸려면 백업을 만드는 `--force`를 사용합니다.
- 설치된 프로젝트의 gate는 이 도구 저장소의 테스트를 실행하지 않습니다. 자체 검사와 규칙 문서 검사, 전체 파일 검사만 수행합니다.
- 자체 검사는 배포본의 기본 규칙으로 엔진을 검증하므로 사용자가 규칙을 바꿔도 엔진 고장으로 판단하지 않습니다. 실제 답변과 문서는 프로젝트 규칙으로 검사합니다.
- 실모델 평가는 고정된 입력으로 진행합니다. 모델, effort, 캐시와 서버 상태에 따라 응답과 시간이 달라집니다. 토큰 수와 실행 시간은 따로 보고합니다.
