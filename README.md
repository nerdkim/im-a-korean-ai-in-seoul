# im-a-korean-ai-in-seoul

Claude Code에서 Claude가 한국어를 자연스럽게 쓰도록 돕는 도구입니다. 프로젝트에 설치하면 Claude는 한국어로 답변, 문서, 코드 주석, 커밋 메시지를 쓰기 전에 `korean-rewrite` skill을 부릅니다. hook은 Claude가 쓴 글을 검사기로 확인합니다. 검사기가 금지 문자나 설치할 때 고른 말투와 다른 어미를 찾으면 hook은 그 글이 파일과 커밋에 남지 않게 막습니다. 답변에서 찾으면 한 번 다시 쓰게 합니다.

## 설치

Claude Code에서 이렇게 요청하면 Claude가 저장소를 읽고 설치합니다.

> https://github.com/nerdkim/im-a-korean-ai-in-seoul 저장소를 읽고 이 프로젝트에 설치해 주십시오.

직접 설치하려면 프로젝트 루트에서 다음 명령을 실행합니다.

```sh
npx -y github:nerdkim/im-a-korean-ai-in-seoul --target . --activate
node .korean-style/scripts/doctor.mjs
```

설치한 뒤에는 Claude Code를 다시 시작합니다. Node.js 20 이상과 npm, Git, Claude Code가 필요합니다. 명령은 macOS, Linux, WSL의 shell에서 실행합니다. 설치 옵션과 설치되는 파일, 팀에서 함께 쓰는 법, 제거하는 법은 [설치와 사용](docs/usage.md)에 있습니다.

## 설치하면 바뀌는 것

- **한국어를 쓰기 전에 skill을 부릅니다.** `korean-rewrite` skill에는 처음부터 한국어로 생각해 쓰는 순서와 고칠 표현이 들어 있습니다. skill의 원칙과 고칠 표현은 Claude가 실제로 쓴 문장, 국립국어원 자료, 국내 회사들이 공개한 글쓰기 가이드, 소프트웨어 현지화 스타일 가이드, 언어 모델을 다룬 연구에서 가져왔습니다. 자료에 없는 규칙은 이 저장소가 따로 정했습니다. 출처는 [한국어 작성 원칙](docs/writing.md)에 있습니다. hook은 Claude가 skill을 불렀는지만 확인하고 skill에 적힌 순서를 모두 따랐는지는 확인하지 않습니다.
- **작성 지침을 켭니다.** 이 도구의 작성 지침은 `korean-style`이라는 output-style입니다. 설치 명령의 `--activate`는 프로젝트의 output-style을 `korean-style`로 바꿉니다. 이미 다른 output-style을 골라 두었어도 바꿉니다. Claude Code는 세션을 시작할 때 작성 지침을 시스템 프롬프트에 넣습니다. 작성 지침에는 말투와 기본 원칙이 들어 있습니다.
- **hook이 Claude가 쓴 한국어를 검사합니다.** 파일에 쓰는 문서와 주석, 커밋 메시지, PR 설명, 답변을 검사기로 확인합니다. 검사기가 따르는 규칙은 규칙 문서(`.korean-style/rules.md`)에 있습니다. 오류가 있거나 skill을 거치지 않은 글은 파일, 커밋, PR에 남지 않게 막고 이런 글이 답변이면 한 번 다시 쓰게 합니다. 다만 기본 규칙에서는 한글이 20자보다 적은 글에 skill을 요구하지 않습니다. hook은 같은 요청에서 skill을 부르지 않았다는 이유로 두 번 막았는데도 Claude가 skill을 부르지 않으면 그 뒤로는 이 이유로 막지 않습니다. 답변은 화면에 나온 뒤에 검사하므로 처음 쓴 답변도 화면에 남습니다.
- **커밋 메시지는 누가 쓰든 검사합니다.** Git 저장소에는 `commit-msg` hook도 설치합니다. 그래서 사람이 직접 하거나 다른 프로그램으로 하는 커밋도 메시지에 오류가 있으면 멈춥니다. 다른 `commit-msg` hook이 이미 있으면 설치 스크립트는 그 hook을 덮어쓰지 않습니다. 이때 사람이 직접 하거나 다른 프로그램으로 하는 커밋도 검사하려면 기존 hook이 검사기를 실행하도록 고쳐야 합니다. 방법은 [설치와 사용](docs/usage.md)에 있습니다.
- **말투를 정해 둡니다.** 기본은 `~합니다`로 끝나는 합니다체입니다. 설치할 때 해요체나 `혼용`을 고를 수도 있습니다. 합니다체를 고르면 검사기가 `~세요`, `~어요` 같은 해요체 어미를 오류로 잡습니다. 해요체를 고르면 `~니다`로 끝나는 어미를 오류로 잡습니다. 검사기가 잡지 못하는 어미는 [제약](docs/limits.md)에 있습니다. `혼용`을 고르면 검사기는 두 말투를 모두 받아들입니다. 대신 skill과 작성 지침에는 답변 하나 안에서는 처음 쓴 말투를 끝까지 지키라는 지시가 들어 있습니다.
- **Claude Code가 커밋과 PR에 생성 표시를 붙이지 않습니다.** 설치 스크립트는 프로젝트 설정(`.claude/settings.json`)의 `attribution`에 `commit`이나 `pr` 값이 없으면 빈 값을 넣어 Claude Code가 `Co-Authored-By: Claude` 줄과 `Generated with [Claude Code]` 줄을 붙이지 않게 합니다. 이런 줄은 검사기도 오류로 잡습니다.
- **팀이 같은 규칙을 씁니다.** 규칙 문서는 저장소에 커밋하는 파일입니다. 저장소를 clone한 팀원이 설치 명령을 한 번 실행하면 같은 규칙이 적용됩니다.

## 설치 전후 비교

요청 열두 가지를 Claude Opus 5.5에 보냈습니다. 요청마다 이 도구를 설치한 프로젝트에서 두 번, 이 도구가 없는 프로젝트에서 두 번 보냈습니다. 요청을 보낼 때마다 새 세션을 열었습니다.
두 프로젝트는 평가 스크립트가 임시 디렉터리에 새로 만들었습니다. 이 도구가 없는 프로젝트는 빈 디렉터리였습니다. 이 도구를 설치한 프로젝트에도 이 도구 말고는 아무것도 없었습니다. hook과 skill은 이 도구를 설치한 프로젝트에서 실제로 동작했습니다. 두 프로젝트에서 모두 Claude가 쓸 수 있는 Claude Code 도구는 Skill, Read, Bash뿐이었습니다. Claude Code는 사용자 설정과 MCP 서버를 불러오지 않았습니다. Claude Code는 이 평가용으로 새로 만든 설정 디렉터리를 썼습니다.
Claude Code 2.1.310에서 effort를 medium으로 두고 2026년 10월 27일(한국 시간)에 실행했습니다. 요청 원문은 [showcase.json](test/fixtures/eval/showcase.json)에 있습니다.

표의 숫자는 이 실행에서 저장한 결과를 `npm run eval -- --summary`로 센 값입니다. 실행 결과는 저장소에 넣지 않습니다. [다시 실행하기](docs/examples.md#다시-실행하기)의 명령으로 같은 비교를 다시 할 수 있지만 답변이 달라지므로 숫자도 달라질 수 있습니다.

이 평가에서 보낸 요청 열두 가지 가운데 다섯 가지는 skill 예문과 같은 낱말이나 문장을 씁니다. Chrome 확장 프로그램 질문에서는 `Profile 11`이, 번역 요청에서는 `allow`, `make sure`, `hook`이 skill 예문에도 나옵니다. 장애 메모에서는 `커넥션 풀`, `파이프라인`, `알림`이, 다듬기 요청에서는 `설정하는 것이 가능합니다`가, 점검 공지에서는 `10월 24일`이 skill 예문에도 나옵니다. 표에서 검사기로 센 해요체 어미, 금지 문자, 생성 표시는 이 예문이 다루는 문제가 아닙니다. 사람이 답변을 읽고 센 머리말, 덧붙인 말, 요청에 없는 내용은 skill 예문과 겹치지 않는 요청 일곱 가지에서도 이 도구를 설치한 프로젝트의 답변에서 더 적게 나왔습니다. 하지만 어떤 낱말을 골랐는지는 skill 예문과 겹치는 요청과 겹치지 않는 요청으로 나눠 비교하지 못했습니다. 그래서 낱말 선택에서 보인 차이는 skill 예문 때문일 수 있습니다. 나눠 센 결과와 기준은 [설치 전후 예시](docs/examples.md#skill-예문과-겹치는-요청)에 있습니다.

표에서 검사기가 찾은 오류는 규칙 문서에 적힌 문제뿐입니다. 요청에 없는 내용을 채우거나 한국어로 굳은 말 대신 영어를 쓰는 문제는 검사기가 잡지 못합니다. 이런 문제는 답변을 직접 읽고 찾아 [설치 전후 예시](docs/examples.md)에 요청마다 적었습니다.

이 도구를 설치한 프로젝트에서 Claude는 답변마다 먼저 skill을 불렀고 PR 설명과 커밋 메시지 요청에서는 검사기도 실행했습니다. skill 본문과 검사기 결과가 입력에 더해지고 Claude Code가 모델을 호출하는 횟수도 늘어 비용과 시간이 더 들었습니다. 비용은 Claude Code가 정가로 계산해 결과에 기록한 금액입니다. 같은 요청을 다시 보냈을 때는 처음 보냈을 때 캐시에 저장된 입력을 다시 읽어 비용이 줄었습니다. 그래서 표에는 처음 보낸 요청과 다시 보낸 요청의 비용을 나눠 적었습니다.

**프로젝트마다 두 번 받은 답변에서 본 것**

- 이 도구가 없는 프로젝트에서 Claude는 첫 번째 답변의 목록 항목을 `502 오류 반환`처럼 명사로 끝내거나 `잘못 들어감`, `처리하지 못함`처럼 `-ㅁ`으로 끝내 문장을 맺지 않았습니다. 슬랙 글 끝에는 해요체 문장 `실패한 결제 건 확인이나 고객 대응이 필요하면 이 스레드에 남겨 주세요.`를 붙였습니다. 두 번째 답변은 해요체 머리말 `Slack에 바로 붙여넣을 수 있게 Slack 서식으로 썼어요.`로 시작했습니다. 제목 앞에는 emoji 코드 `:rotating_light:`를 넣었고 슬랙 글 끝에는 `:pray:`를 넣었습니다. 슬랙 글 뒤에는 해요체 문단을 하나 더 붙여 메모에 없는 내용 네 가지를 확인하라고 했습니다. 원인 항목에는 두 번 모두 메모에 없는 설명을 더했습니다. 첫 번째 답변은 커넥션이 부족해 요청을 처리하지 못했다고 썼고 두 번째 답변은 커넥션 풀이 가득 차 요청이 처리되지 못했다고 썼습니다. 첫 번째 답변은 이 설명이 추정이라고 밝히지 않았습니다. 두 번째 답변은 덧붙인 문단에서 추론이라고 밝혔습니다.
- 이 도구를 설치한 프로젝트에서 Claude는 두 번 모두 머리말과 덧붙인 말 없이 슬랙 글만 합니다체로 썼고 메모에 없는 설명도 넣지 않았습니다. 두 번째 답변의 `커넥션 풀이 포화되면 알림이 오도록 추가합니다.`에는 무엇을 추가하는지가 빠졌습니다. 첫 번째 답변에서는 같은 조치를 `커넥션 풀이 포화되면 알림이 오도록 설정합니다.`라고 썼습니다. 두 번 모두 `14:32에 롤백했고,`처럼 연결 어미 뒤에 쉼표를 찍었습니다.
- 두 프로젝트의 답변 네 개에는 모두 메모에 적힌 시각, 원인, 조치, 영향, 후속 조치가 빠짐없이 들어 있었습니다. `커넥션 풀`, `파이프라인`, `알림`처럼 메모에 나온 한국어 용어를 영어로 바꾼 답변은 없었습니다. 이 도구가 없는 프로젝트의 두 번째 답변에도 `커넥션 풀이 가득 찰 때 알림이 오도록 추가`처럼 무엇을 추가하는지 빠진 항목이 있었습니다.
